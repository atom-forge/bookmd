# Presentation structure and visual narrative

## Objectives

Students will be able to build a short, easy-to-follow project presentation in which every slide supports one main claim. They will deliberately choose images, text, and live prototype demonstrations rather than treating a tour of the full working file as a presentation.

## One story, not a document repository

> [!note] Key idea
> A 5–10-minute presentation has no room for every note, decision, and screen. Choose the story's backbone: who the user is, what the problem is, what research revealed, how it changed the design, what you tested, and the result. The audience should always understand why they are seeing a slide and how it connects to the previous one.

Give each slide one main claim. Excessive text usually means the speaker's notes have ended up on the canvas. Slides should support the message: a quote, flow excerpt, or before-and-after comparison often says more than a list. Add details verbally rather than in tiny text.

## Suggested structure

1. Situation, target user, and problem.  
2. Research evidence and insight.  
3. Task flow or design principle.  
4. The prototype's key solution.  
5. Test and finding.  
6. Iteration, result, limitation, and next step.

This is a logical sequence, not a mandatory slide count. If evidence did not change a decision, it probably does not belong in the main story. If a solution matters but lacks evidence, describe it as an experiment or open hypothesis.

## Demonstrating a live prototype

A live prototype can be powerful but risky: a broken link, slow loading, or an unexpected state can distract the audience. Show only the short task that demonstrates the story's key decision. Have a tested route and backup screenshots ready. Guide the audience through the user task rather than navigating among Figma frames.

## Common misconceptions

| Statement | Clarification |
| --- | --- |
| “More screens mean a more thorough presentation.” | Detail is not the same as clarity. |
| “The design speaks for itself.” | Without reasoning and evidence, the audience can comment only on taste. |

## Review questions

1. Does every slide have a one-sentence main claim?
2. Which slide shows your strongest evidence?
3. What will you show live, and why that part?
4. Which detail belongs in an appendix instead?

## Glossary

**Visual narrative:** a coherent story conveyed through images, text, and sequence.  
**Main claim:** the essential message communicated by a slide.  
**Appendix:** details unnecessary for the main story but available for later reference.  
**Live demo:** a real-time, task-focused demonstration of a prototype or product.
