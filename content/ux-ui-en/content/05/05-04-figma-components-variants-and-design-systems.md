# Figma – Components, variants, and design systems

## Objective

Create reusable components and organize common states into variants. A component is more than a graphic that can be copied: it also supports consistent labels, navigation, and feedback.

## Connection to the course

> [!note] Key idea
> Choose a recurring information architecture element, such as a navigation row, search field, or result card. Turn it into a component and create default, selected, or empty states. Check whether labels and states convey the same mental model in every occurrence.

## Rules instead of repetition

A **component** is an interface element designed once and used as instances in several places. A search field, for example, may contain an icon, label, input area, and error state. When you improve the main component, its **instances** can follow the change. This does more than speed up editing: it reduces the chance that the same element behaves differently on two screens.

A **variant** organizes meaningful states of the same component. A button may be in its default, pressed, disabled, or loading state; these are different situations for one functional element rather than four unrelated buttons. A **design system** is a broader shared language: components, styles, names, and usage rules together. A mini design system is already useful if you consistently document what a few elements are for and when to use each state.

## Terms

**Component:** a reusable, centrally editable interface element.  
**Instance:** a specific occurrence of a component used on a screen.  
**Variant:** a coordinated state or type within a set of related forms of the same component.  
**Design system:** a design framework consisting of shared elements and rules.
